# TASK: JobRadar Extension - модуль ручного анализа вакансий hh.ru

## 0. Контекст для агента

Ты работаешь в существующем репозитории **JobRadar** (Python 3.11, aiogram-бот, aiohttp веб-сервер, SQLite через `src/database.py`, конфиг через `src/config.py`). Проект уже умеет:

- хранить в SQLite (`data/jobradar.db`);

Ты добавляешь **новый модуль внутри этого же репозитория**, а не отдельный проект. Ниже - обоснование и полное ТЗ.

## 1. Технический вывод: модуль, а не новый проект

**Решение: расширять JobRadar, не создавать новый проект с нуля.**

Обоснование:

1. В JobRadar уже поднят и настроен aiohttp веб-сервер (`WEB_SERVER_HOST`, `WEB_SERVER_PORT`, обработчик cron-запросов). Добавить один новый POST-роут `/api/extension/analyze` - это 30-40 строк, а не новый сервис.
2. Уже есть `src/database.py` с логикой дедупликации откликов (`vacancy_log`). Для нового модуля нужна ровно такая же логика: "не гонять повторно одну и ту же вакансию через ИИ". Переиспользуем паттерн, добавляем одну таблицу.
3. Уже есть `src/config.py` и `.env` - туда просто добавляется `OPENROUTER_API_KEY` и `OPENROUTER_MODEL`.
4. Хранить ключ OpenRouter **на бэкенде**, а не в браузерном расширении - правильнее с точки зрения безопасности: содержимое `chrome.storage` в расширении читается через `chrome://extensions` → "Инспектировать" любым, кто имеет доступ к браузеру или ворует профиль. Ключ на сервере (в `.env`, который и так не коммитится) читается только процессом Python.
5. Единственная реально новая часть - это **браузерное расширение** (content script + плавающая кнопка + оверлей), потому что старый `hh_client.py` работает через HTTP+cookie и не видит "живую" DOM-страницу, которую ты сам листаешь руками. Это разные принципы получения данных, их незачем тащить в один файл - но незачем и разносить по разным репозиториям и разным серверам.

Итог по архитектуре:

```
JobRadar/                          <- существующий репозиторий, ничего не ломаем
├── src/
│   ├── ... (существующее без изменений)
│   ├── extension_profile.py       <- НОВОЕ: текстовый профиль соискателя (резюме для промпта)
│   ├── extension_prompt.py        <- НОВОЕ: сборка промпта для OpenRouter
│   ├── extension_service.py       <- НОВОЕ: вызов OpenRouter, парсинг ответа
│   └── database.py                <- ПРАВКА: + таблица extension_analysis (см. п.5)
├── main.py                        <- ПРАВКА: регистрация нового роута в aiohttp
└── extension/                     <- НОВОЕ: браузерное расширение (отдельная папка, свой package)
    ├── manifest.json
    ├── content_script.js
    ├── overlay.css
    ├── background.js
    ├── options.html
    ├── options.js
    └── icons/
```

Никакого нового репозитория, нового Telegram-бота или второй базы данных создавать не нужно.

## 2. Как работает модуль (пользовательский сценарий)

1. Пользователь листает hh.ru в обычном браузере, залогинен в своём аккаунте как обычно.
2. Открывает интересную вакансию на `hh.ru/vacancy/...`.
3. Content script расширения находит страницу вакансии, инжектит **плавающую кнопку** в правый нижний угол (см. п.6 - UI).
4. Пользователь кликает по кнопке → расширение скрапит DOM страницы, вырезает нужные блоки (см. п.3), формирует JSON и отправляет POST-запрос на локальный бэкенд JobRadar (`http://127.0.0.1:8080/api/extension/analyze` по умолчанию, адрес настраивается в options-странице расширения).
5. Бэкенд:
   - проверяет, анализировалась ли эта вакансия раньше (по `hh_vacancy_id`), если да - отдаёт сохранённый результат без повторного запроса к ИИ;
   - иначе собирает промпт из профиля соискателя + данных вакансии, шлёт в OpenRouter (`google/gemini-2.5-flash-lite`), получает структурированный JSON-ответ, сохраняет в SQLite, возвращает расширению.
6. Расширение показывает **оверлей поверх страницы hh.ru** с вердиктом (подходит / не подходит + краткие причины) и, если подходит, - готовым текстом отклика с кнопкой "Скопировать".
7. Пользователь копирует текст и вручную вставляет его в отклик на hh.ru (кнопку "Откликнуться" нажимает сам - никакой автоотправки в этом модуле нет, это осознанно на усмотрение пользователя).

## 3. Что и как скрапить с страницы вакансии

Работаем с текущим DOM `hh.ru/vacancy/<id>`. hh.ru активно использует атрибуты `data-qa="..."` для разметки - они меняются реже, чем CSS-классы, но всё равно могут отличаться от версии к версии. **Агент обязан перед реализацией открыть реальную страницу вакансии на hh.ru через DevTools и свериться с актуальными `data-qa`, а не полагаться слепо на список ниже.**

Ожидаемые (по состоянию на момент написания ТЗ, ТРЕБУЮТ ПРОВЕРКИ) точки входа:

| Данные | Ожидаемый селектор-подсказка | Фолбэк-стратегия |
|---|---|---|
| Название вакансии | `[data-qa="vacancy-title"]` | `document.title`, отрезать " - вакансия ..." |
| Зарплата | `[data-qa="vacancy-salary"]` | искать блок рядом с заголовком, где текст содержит "₽", "руб", "USD", "EUR" |
| Опыт работы | `[data-qa="vacancy-experience"]` | текстовый поиск по фразам "Нет опыта", "От 1 года", "От 3 лет" |
| Занятость / график / формат работы | `[data-qa="vacancy-view-employment-mode"]` | искать блок-список условий рядом с зарплатой (обычно один `<p>` через запятую: "Полная занятость, полный день, гибрид") |
| Описание вакансии | `[data-qa="vacancy-description"]` | брать `innerText` контейнера с описанием |
| Ключевые навыки (граница обрезки) | `[data-qa="skills-element"]` или заголовок с текстом "Ключевые навыки" | искать в тексте описания подстроку "Ключевые навыки" и обрезать всё, что после неё |
| ID вакансии | из URL `hh.ru/vacancy/(\d+)` | - |

Правило обрезки описания: **сохраняем весь текст описания вакансии от начала до заголовка "Ключевые навыки" включительно (сам заголовок отбрасываем).** Если заголовка нет - берём текст описания целиком.

Очистка текста перед отправкой (обязательно реализовать функцию `cleanVacancyText()` в `content_script.js`):
- убрать HTML-теги, оставить только текст с переносами строк между абзацами и пунктами списков (`<li>` → "- пункт");
- схлопнуть повторяющиеся пустые строки (не больше одной подряд);
- обрезать пробелы по краям;
- убрать невидимые юникод-символы (`\u200b`, `\ufeff` и т.п.), которые hh.ru иногда вставляет.

Собранный объект, который content script отправляет в background/бэкенд:

```json
{
  "hh_vacancy_id": "123456789",
  "url": "https://hh.ru/vacancy/123456789",
  "title": "Junior QA инженер",
  "conditions": {
    "salary": "от 80 000 до 120 000 руб. на руки",
    "employment": "Полная занятость",
    "schedule": "Полный день",
    "work_format": "Гибрид",
    "experience": "Нет опыта"
  },
  "description": "текст описания без ключевых навыков...",
  "scraped_at": "2026-07-09T12:00:00Z"
}
```

Если какое-то поле не найдено на странице - отправлять `null`, а не выдуманное значение. Промпт должен уметь работать с частично пустыми условиями.

### 5.3 `src/extension_service.py` - новый файл

Обязанности:
1. Принять словарь вакансии (уже провалидированный роутом).
2. Проверить кэш через `database.get_extension_analysis`.
3. Если кэша нет - вызвать OpenRouter через `httpx` (в проекте уже используется `httpx`/`aiohttp`, свериться с `requirements.txt` и использовать то, что уже есть в проекте, не добавлять новую HTTP-библиотеку без необходимости).
4. Распарсить JSON-ответ модели. **Обязательно** обернуть парсинг в try/except: модель иногда оборачивает JSON в ```json fence - учесть и это.
5. Сохранить результат в БД.
6. Вернуть результат роуту.

Пример вызова OpenRouter (эндпоинт OpenAI-совместимый):

```python
import httpx

OPENROUTER_URL = "https://openrouter.ai/api/v1/chat/completions"

async def call_openrouter(system_prompt: str, user_prompt: str, api_key: str, model: str) -> str:
    async with httpx.AsyncClient(timeout=60) as client:
        resp = await client.post(
            OPENROUTER_URL,
            headers={
                "Authorization": f"Bearer {api_key}",
                "Content-Type": "application/json",
            },
            json={
                "model": model,
                "messages": [
                    {"role": "system", "content": system_prompt},
                    {"role": "user", "content": user_prompt},
                ],
                "temperature": 0.4,
            },
        )
        resp.raise_for_status()
        data = resp.json()
        return data["choices"][0]["message"]["content"]
```

### 5.4 `main.py` - новый роут aiohttp

Добавить рядом с существующей регистрацией cron-роута (посмотреть, как там оформлен `app.router.add_get`/`add_post`, и оформить в том же стиле):

```python
from aiohttp import web
from src.extension_service import analyze_vacancy
from src.config import EXTENSION_ENDPOINT_SECRET

async def handle_extension_analyze(request: web.Request) -> web.Response:
    if request.headers.get("X-Extension-Secret") != EXTENSION_ENDPOINT_SECRET:
        return web.json_response({"error": "forbidden"}, status=403)

    try:
        payload = await request.json()
    except Exception:
        return web.json_response({"error": "bad json"}, status=400)

    if not payload.get("hh_vacancy_id"):
        return web.json_response({"error": "hh_vacancy_id required"}, status=400)

    result = await analyze_vacancy(payload)
    return web.json_response(result)

# в функции, где регистрируются остальные роуты:
app.router.add_post("/api/extension/analyze", handle_extension_analyze)
```

**Важно:** этот эндпоинт слушает на том же `WEB_SERVER_HOST:WEB_SERVER_PORT`, что и cron. Если сервер уже поднят локально командой `python main.py`, расширение будет стучаться на `http://127.0.0.1:8080` (или тот адрес, что задан в `.env`). Отдельно поднимать ничего не нужно.

## 6. Браузерное расширение (`extension/`)

Manifest V3, Chrome/Edge (Chromium-based). Без сборщиков и фреймворков - чистый JS, чтобы не плодить зависимости (принцип "умная лень").

### 6.1 `manifest.json`

```json
{
  "manifest_version": 3,
  "name": "JobRadar - анализ вакансий hh.ru",
  "version": "1.0.0",
  "description": "Анализирует открытую вакансию hh.ru через ИИ и готовит отклик",
  "permissions": ["storage", "activeTab"],
  "host_permissions": ["https://hh.ru/*", "http://127.0.0.1:8080/*", "http://localhost:8080/*"],
  "background": { "service_worker": "background.js" },
  "content_scripts": [
    {
      "matches": ["https://hh.ru/vacancy/*"],
      "js": ["content_script.js"],
      "css": ["overlay.css"],
      "run_at": "document_idle"
    }
  ],
  "action": { "default_title": "JobRadar" },
  "options_page": "options.html",
  "icons": { "128": "icons/icon128.png" }

`host_permissions` на `127.0.0.1`/`localhost` покрывает случай локального запуска. Если пользователь задеплоит JobRadar на внешний адрес - в options-странице просто указывается другой URL, и это поле в манифесте нужно будет расширить (агенту заранее оставить это как заметку в options.html: "если бэкенд на другом адресе - впиши его сюда, и добавь этот адрес в manifest.json host_permissions").

   - const settings = await chrome.storage.local.get(['endpoint', 'secret'])
   - fetch(settings.endpoint + '/api/extension/analyze', { POST, JSON, header X-Extension-Secret })
   - показать оверлей с результатом или с ошибкой сети/сервера

3. scrapeVacancyPage() -> строит объект как в п.3 этого файла

4. cleanVacancyText(rawHtml) -> строка, см. правила очистки в п.3

5. showOverlay(state, data)
   states: 'loading' | 'error' | 'result'
   - создаёт/обновляет div#jr-overlay с фоном-затемнением под ним (полупрозрачный backdrop)
   - оверлей закрывается по клику на backdrop, по Escape и по кнопке "✕"
   - в состоянии result:
     - если fit === true: зелёный акцент, "Вакансия подходит", список причин,
       текст отклика в <textarea readonly>, кнопка "Скопировать текст отклика"
     - если fit === false: нейтральный/приглушённый акцент, "Вакансия не подходит",
       список причин, без текстового поля
   - кнопка "Скопировать" -> navigator.clipboard.writeText(...), временно
     меняет текст кнопки на "Скопировано ✓" на 1.5 секунды
```

### 6.3 `background.js`

Минимальная роль в MV3: можно оставить пустым service worker-заглушкой либо (по желанию агента) вынести туда fetch-запрос вместо content script, если возникнут проблемы с CORS у `hh.ru` origin при прямом fetch с content script на `127.0.0.1`. **Агенту явно проверить в рантайме**: если `fetch` из content script на `localhost` блокируется CORS/mixed-content политикой браузера - перенести вызов в `background.js` (там таких ограничений нет) и общаться через `chrome.runtime.sendMessage`.

### 6.4 `options.html` / `options.js`

Простая страница настроек с двумя полями:
- "Адрес бэкенда JobRadar" (по умолчанию `http://127.0.0.1:8080`)
- "Секретный ключ расширения" (значение из `EXTENSION_ENDPOINT_SECRET`)

Сохранение через `chrome.storage.local.set(...)`, кнопка "Сохранить", подтверждение "Настройки сохранены ✓". Всё на русском.

## 7. Визуал оверлея и кнопки (обязательно соблюсти)

Пользователь ценит спокойный, нешумный, тёмный минимализм без "маркетингового" шума. Требования:

- Тёмный полупрозрачный backdrop (`rgba(10, 10, 12, 0.6)`), сам оверлей - карточка на тёмном нейтральном фоне (`#161618` или близко), без градиентов, без ярких неоновых цветов.
- Акцентный цвет для "подходит" - приглушённый зелёный (не кислотный), для "не подходит" - нейтральный серый, никакого агрессивного красного (это не ошибка, а просто нерелевантная вакансия).
- Шрифт системный (`-apple-system, Segoe UI, Roboto, sans-serif`), без декоративных шрифтов.
- Плавающая кнопка маленькая, не перекрывает контент hh.ru, при наведении - лёгкое затемнение/подъём тени, без анимации "прыжков" или пульсации.
- Никакого текста на английском в интерфейсе - все подписи, кнопки, состояния ("Анализирую...", "Скопировано ✓", "Вакансия не подходит") только на русском.
- Оверлей должен закрываться без потери результата анализа, если пользователь случайно кликнул мимо - можно повторно открыть последний результат повторным кликом по плавающей кнопке (не гонять OpenRouter повторно, просто показать закэшированный ответ, который уже отдал бэкенд, - хранить последний результат в `chrome.storage.session` или просто в переменной модуля).

- Не вводить платные сервисы по умолчанию. OpenRouter с моделью `google/gemini-2.5-flash-lite` выбран как бесплатный/дешёвый вариант - явно оставить возможность сменить модель через `.env` (`OPENROUTER_MODEL`), не хардкодить.

## 12. Риски и что учесть отдельно

- **DOM hh.ru меняется.** Селекторы из п.3 - отправная точка, не финальная истина. Заложить текстовые фолбэки (поиск по ключевым словам вместо только `data-qa`), чтобы модуль не ломался полностью при мелких вёрстка-правках hh.ru.
- **CORS/mixed content.** Если `hh.ru` (https) не даёт content script стучаться на `http://127.0.0.1` - переносить fetch в `background.js` (см. п.6.3). Это стандартное для MV3 решение, а не проблема архитектуры.
- **Модель иногда не возвращает чистый JSON.** Обязательно защититься от ```json-обёртки и лишнего текста до/после JSON при парсинге ответа OpenRouter.
- **Ручной режим - это фича, не баг.** Никакого давления в сторону автоматизации отклика в рамках этого модуля не нужно - пользователь сознательно хочет ручной контроль над финальной отправкой.
